`datetimepicker` shows a date field and a time field side by side, which set a single Unix
timestamp together. The date field opens the same calendar as the [date picker](/elements/date-picker)
and the time field the same hourly list as the [time picker](/elements/time-picker), typeable for a
time off the hour. Slack allows it in `actions` blocks, section accessories, and `input` blocks, but
not in App Home.

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "input",
        block_id: "when",
        label: { type: "plain_text", text: "Starts at" },
        element: {
          type: "datetimepicker",
          action_id: "starts_at",
          initial_date_time: 1767261600,
        },
      },
    ],
  }}
/>

:::note
`datetimepicker` has no `placeholder` field: Slack always shows "Select a date" and "Time" in its
two fields until a value is chosen.
:::

## Examples

### Without an initial value

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "actions",
        elements: [{ type: "datetimepicker", action_id: "starts_at" }],
      },
    ],
  }}
/>

The fields show their placeholders ("Select a date" / "Time") until the user picks either part.
Picking a day first fills the time with the current time, to the minute; picking a time first
fills the date with today, which the date field calls "Today".

### With a confirmation dialog

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "actions",
        elements: [
          {
            type: "datetimepicker",
            action_id: "starts_at",
            initial_date_time: 1718461800,
            confirm: {
              title: { type: "plain_text", text: "Change the start time?" },
              text: { type: "mrkdwn", text: "This will reschedule the event." },
              confirm: { type: "plain_text", text: "Do it" },
              deny: { type: "plain_text", text: "Cancel" },
            },
          },
        ],
      },
    ],
  }}
/>

The dialog appears after the user picks a date or a time, before the new value takes effect.

## Interactivity

Every change fires an action straight away, as in Slack: picking a day, picking or typing a time,
and "Clear selection". `selected_date_time` is a Unix timestamp in seconds, and `null` once cleared.
When the element has an `initial_date_time`, the action echoes it:

```json
{
  "type": "datetimepicker",
  "action_id": "starts_at",
  "block_id": "when",
  "selected_date_time": 1718872500,
  "initial_date_time": 1718461800
}
```

Once a value is chosen, "Clear selection" leads the time list and is the calendar's footer.
It empties both fields and sends `"selected_date_time": null`.

The same shape lands in `state.values[block_id][action_id]`:

```json
{
  "type": "datetimepicker",
  "selected_date_time": 1718872500
}
```

When `initial_date_time` is set, that value is reported as state as soon as the element mounts,
before any interaction.

### Time zone

`BlockKitProvider`'s `timeZone` prop (an IANA zone like `Europe/Amsterdam`) is the zone the picker
works in. The fields show the date and time in it, the calendar opens on that wall-clock date, "Today"
and the current time are read in it, and the date and time the user picks are read in it: picking 11:00 on 1 January 2026 with
`Europe/Amsterdam` sends `1767261600` (10:00 UTC). The hint underneath names the zone (e.g. "Time
zone: Amsterdam, Berlin, Bern, Rome, Stockholm, Vienna"). `selected_date_time` itself is always a
Unix timestamp, exactly as Slack sends it. On a daylight saving change, a time the clocks skip moves
forward by the gap and a time they repeat takes its first occurrence. Without a `timeZone` prop, the
picker works in UTC.
