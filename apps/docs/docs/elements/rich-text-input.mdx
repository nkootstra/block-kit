`rich_text_input` collects text and hands it back as a `rich_text` block, the same structure Slack
uses for a message composed in its own WYSIWYG editor. It's an `input`-block-only element: it
doesn't appear in an `actions` block or as a section accessory, and, like `file_input`, Slack only
supports it in modals, not Home tabs.

<Preview
  payload={{
    type: "modal",
    title: { type: "plain_text", text: "New entry" },
    submit: { type: "plain_text", text: "Save" },
    close: { type: "plain_text", text: "Cancel" },
    blocks: [
      {
        type: "input",
        block_id: "summary",
        label: { type: "plain_text", text: "Summary" },
        element: {
          type: "rich_text_input",
          action_id: "summary_input",
          placeholder: { type: "plain_text", text: "Write something" },
        },
      },
    ],
  }}
/>

:::note
The field is drawn like Slack's composer: the formatting bar above it (bold, italic, lists, links,
and so on) and a row under it with **Aa** and an emoji button. **Aa** hides and shows the formatting
bar. The editor itself is plain text, so the formatting buttons are marked unavailable (they dim
until the field has focus, as Slack's do), and the emoji button is unavailable until block-kit has
an emoji picker. Typing into the field works normally.
:::

## Examples

### With an initial value

<Preview
  payload={{
    blocks: [
      {
        type: "input",
        block_id: "notes",
        label: { type: "plain_text", text: "Release notes" },
        element: {
          type: "rich_text_input",
          action_id: "notes_input",
          initial_value: {
            type: "rich_text",
            elements: [
              {
                type: "rich_text_section",
                elements: [{ type: "text", text: "Fixed the login redirect loop." }],
              },
            ],
          },
        },
      },
    ],
  }}
/>

`initial_value` takes a full `rich_text` block, the same shape you'd get back from the element
itself, not a plain string.

### Sizing the field

<Preview
  payload={{
    blocks: [
      {
        type: "input",
        block_id: "bio",
        label: { type: "plain_text", text: "Bio" },
        element: {
          type: "rich_text_input",
          action_id: "bio_input",
          min_lines: 5,
          placeholder: { type: "plain_text", text: "Tell the team about yourself" },
        },
      },
    ],
  }}
/>

`min_lines` sets the field's starting height; `max_lines` (8 by default) caps how tall it grows
before it scrolls.

## Interactivity

In an input block with `dispatch_action: true`, the field calls `onAction` with its content wrapped
as a `rich_text` block, under `rich_text_value`, on the trigger in `dispatch_action_config`: Enter
by default (Shift+Enter adds a line), or `on_character_entered`, once typing pauses for 300ms.
Without `dispatch_action`, typing only updates `state.values`, as in Slack:

```json
{
  "type": "rich_text_input",
  "action_id": "notes_input",
  "block_id": "notes",
  "action_ts": "1706000000.000100",
  "rich_text_value": {
    "type": "rich_text",
    "elements": [
      {
        "type": "rich_text_section",
        "elements": [{ "type": "text", "text": "Fixed the login redirect loop." }]
      }
    ]
  }
}
```

### Reading the value

Every edit (and the initial value, if any) is written to `state.values` as `{ type, rich_text_value
}`:

```json
{
  "notes": {
    "notes_input": {
      "type": "rich_text_input",
      "rich_text_value": {
        "type": "rich_text",
        "elements": [
          {
            "type": "rich_text_section",
            "elements": [{ "type": "text", "text": "Fixed the login redirect loop." }]
          }
        ]
      }
    }
  }
}
```
