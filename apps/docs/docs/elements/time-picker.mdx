`timepicker` is a field you can type a time into, with a list of the day's hours under it. Use it
in an `actions` block or a section's accessory for a quick pick, or in an `input` block to collect a
time in a modal.

Like Slack's, the field is a text input (`role="combobox"`). Clicking it opens the list, hour by
hour from 12:00 AM, with nothing highlighted; reopened, the field holds the chosen time as selected
text, so typing replaces it. As in Slack, typing doesn't filter or highlight the list: Enter reads
what you typed, so `2:15 PM`, `2:15pm` or `14:15` is picked and sent as typed (`"14:15"`), and text
that isn't a time is ignored, leaving the list open. The arrow keys highlight a row (the first press
starts at 12:00 AM), Enter picks the highlighted time over anything typed, and Escape or Tab closes
the list and puts the chosen time back.

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "actions",
        block_id: "meeting",
        elements: [
          {
            type: "timepicker",
            action_id: "select_time",
            initial_time: "13:37",
            placeholder: { type: "plain_text", text: "Select time" },
          },
        ],
      },
    ],
  }}
/>

## Examples

### Without an initial value

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "actions",
        elements: [
          { type: "timepicker", action_id: "select_time" },
          {
            type: "button",

The closed control shows the `placeholder` text, or "Select time" if none is given, until a time

### With a time zone

Setting `timezone` shows a hint underneath the control naming the zone the way Slack does, after
its own region list rather than the IANA id: `America/New_York` reads "Time zone: Eastern Time (US
and Canada)", `Europe/Madrid` "Time zone: Amsterdam, Berlin, Bern, Rome, Stockholm, Vienna", and
`UTC` "Time zone: Monrovia, Reykjavik". The names were recorded from Block Kit Builder for every
zone browsers know; a zone it doesn't name shows its IANA id.

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "actions",
        elements: [
          {
            type: "timepicker",
            action_id: "select_time",
            initial_time: "13:37",
            timezone: "America/Los_Angeles",
          },
        ],
      },
    ],
  }}
/>

`timezone` is a display hint only: it labels the picker but doesn't shift `initial_time` or the
options list, which are always plain `HH:mm` wall-clock values. It's unrelated to the `timeZone`
prop on `BlockKitProvider`, which controls how _other_ elements (like `datetimepicker`) format
their values for display.

## Interactivity

Picking a time, from the list or typed, fires an action with `selected_time`. In an input block,
the list is as wide as the field. Where the time may be left empty (an `optional` input block, or
any input block in a message), the list starts with "Clear selection" once a time is set, and
clearing sends `null`:

```json
{
  "type": "timepicker",
  "action_id": "select_time",
  "block_id": "meeting",
  "selected_time": "15:00"
}
```

The same shape lands in `state.values[block_id][action_id]`:

```json
{
  "type": "timepicker",
  "selected_time": "15:00"
}
```

When `initial_time` is set, the action carries it too (`"initial_time": "13:37"`), as Slack's does.
It's also reported as state as soon as the element mounts, before any interaction.

:::note
Unlike `datepicker`, `timepicker` has no "clear" affordance. Once a time is selected, picking a
different option is the only way to change it.
:::
