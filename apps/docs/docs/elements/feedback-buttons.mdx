`feedback_buttons` renders a pair of thumbs-up and thumbs-down icon buttons, as seen under an
AI agent's response in Slack. As in Slack, the pair is a radio group labelled "Rating": the picked
thumb stays checked and turns filled, and the arrow keys move between the two. It's a
`context_actions` block element,
so it's typically placed alongside an [icon button](/elements/icon-button) rather than in an
`actions` row.

<Preview
  payload={{
    blocks: [
      {
        type: "context_actions",
        elements: [
          {
            type: "feedback_buttons",
            action_id: "feedback",
            positive_button: {
              text: { type: "plain_text", text: "Good response" },
              value: "positive",
            },
            negative_button: {
              text: { type: "plain_text", text: "Bad response" },
              value: "negative",
            },
          },
        ],
      },
    ],
  }}
  actions
/>

      required: true,

    action_id: {
      type: "string",

        "Identifies this action in the interaction payload. Must be unique within the block. Maximum length is 255 characters.",

:::note
`accessibility_label` on either button's `text` label is read by screen readers instead of that
button's `text`, same as on a plain button.
:::

## Interactivity

Clicking a thumb dispatches a `feedback_buttons` action carrying that button's `value` and `text`:

```json
{
  "type": "feedback_buttons",
  "action_id": "feedback",
  "block_id": "b1",
  "action_ts": "1706000000.000100",
  "value": "positive",
  "text": { "type": "plain_text", "text": "Good response", "emoji": true }
}
```

Every pick sends an action, including picking the thumb that's already checked, and picking with the
arrow keys. Choosing the other thumb moves the check to it. Slack doesn't record feedback buttons in
`state.values`, and neither does the package.
