`datepicker` opens a calendar popup for choosing one date. Use it in an `actions` block or a
section's accessory for a quick date pick, or in an `input` block to collect a date in a modal.

As in Slack, you can also type a date into the field: `05/01/1990`, `5/1/90`, `1990-05-01`,
`May 1, 1990` or the field's own long form, `May 1st, 1990`. Enter takes it and keeps the calendar
open, leaving the field takes it too, and text that isn't a date is ignored; Escape puts the chosen
date back.

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "actions",
        block_id: "trip",
        elements: [
          {
            type: "datepicker",
            action_id: "select_date",
            initial_date: "1990-04-28",
            placeholder: { type: "plain_text", text: "Select a date" },
          },
        ],
      },
    ],
  }}
/>

Like Slack, the field comes in two sizes: the compact 28px field in messages, and the 36px field
with 15px text in modals and on App Home.

## Examples

### Without an initial value

Empty until the user picks a date. The input shows the `placeholder` text, or "Select a date" if
none is given.

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "actions",
        elements: [{ type: "datepicker", action_id: "select_date" }],
      },
    ],
  }}
/>

### With an initial value

Outside an `input` block, the closed control shows the date as Slack does on the web:
`MM/DD/YYYY`.

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "actions",
        elements: [
          {
            type: "datepicker",
            action_id: "select_date",
            initial_date: "1990-04-28",
            placeholder: { type: "plain_text", text: "Select a date" },
          },
        ],
      },
    ],
  }}
/>

### Inside an input block

An `input` block spells the date out instead, e.g. "April 28th, 1990":

<Preview
  payload={{
    blocks: [
      {
        type: "input",
        block_id: "birthday",
        label: { type: "plain_text", text: "Label" },
        element: {
          type: "datepicker",
          action_id: "datepicker-action",
          initial_date: "1990-04-28",
          placeholder: { type: "plain_text", text: "Select a date" },
        },
      },
    ],
  }}
/>

### With a confirmation dialog

<Preview
  actions
  payload={{
    blocks: [
      {
        type: "actions",
        elements: [
          {
            type: "datepicker",
            action_id: "select_date",
            initial_date: "2024-06-15",
            confirm: {
              title: { type: "plain_text", text: "Change the date?" },
              text: { type: "mrkdwn", text: "This will reschedule the trip." },
              confirm: { type: "plain_text", text: "Do it" },

            },
          },
        ],
      },
    ],
  }}
/>

The dialog appears before a pick (or a "Clear selection") takes effect; declining leaves the
element unchanged.

## Interactivity

Picking a day fires an action with `selected_date`. Where the date may be left empty, the calendar
also has Slack's "Clear selection" footer once a date is set, and clearing sends `null`. That's an
`optional` input block, or any input block in a message, where Slack treats inputs as optional:

```json
{
  "type": "datepicker",
  "action_id": "select_date",
  "block_id": "trip",
  "selected_date": "2024-06-20"
}
```

The same shape lands in `state.values[block_id][action_id]` for reading back later, e.g. from a
`view_submission` payload:

```json
{
  "type": "datepicker",
  "selected_date": "2024-06-20"
}
```

When `initial_date` is set, the action carries it too (`"initial_date": "2024-06-01"`), as Slack's
does; the placeholder isn't sent. The initial value is also reported as state as soon as the
element mounts. You don't need an interaction first to read it back.

### Keyboard

As in Slack, the calendar opens with its right edge on the field's (on a screen too narrow for that,
it shifts just enough to stay inside the window), and opening it with a click focuses the selected day (or today). Tabbing into the field opens the calendar too but leaves focus
in the field, so you can type a date or Tab on; the next Tab reaches the field's own "Open calendar"
button, which opens the calendar on the selected day, as Slack's does. ArrowDown in the field also
moves into the calendar, which Slack's field doesn't do; it's kept as a shortcut. There, the
arrow keys move a day left or right and a week up or down, turning the month when they cross its
edge, and Enter picks the focused day. The focused day shows the focus ring over Slack's hover wash,
and each day is named in full for screen readers ("Saturday, April 28th, 1990"), as in Slack. The
month grid is a single tab stop. Picking a day or
pressing Escape closes the calendar and returns focus to the field. The
[datetime picker](/elements/datetime-picker)'s calendar uses the same arrow keys.
