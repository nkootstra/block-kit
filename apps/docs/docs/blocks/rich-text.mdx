`rich_text` is Slack's most expressive text block: paragraphs, lists, quotes, and code, each built
from styled runs and mentions rather than a markdown string. It's what Slack's WYSIWYG message
composer outputs, and what a `rich_text_input` element returns on submit. Reach for it whenever
you need structure `mrkdwn` can't express, like nested lists or a fenced code block.

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "text", text: "Ship it, " },
              { type: "user", user_id: "U0ADA" },
              { type: "text", text: "! Don't forget to update " },
              { type: "channel", channel_id: "C0RELEASES" },
              { type: "text", text: " and loop in " },
              { type: "usergroup", usergroup_id: "S0ENG" },
              { type: "text", text: ".", style: { bold: true } },
            ],
          },
        ],
      },
    ],
  }}
/>

## Fields

<TypeTable
  type={{
    type: {
      type: "string",
      description: "Always `rich_text`.",
      required: true,
    },
    elements: {
      type: "RichTextBlockElement[]",
      description: "The block's top-level content, in order.",
      required: true,
    },
    block_id: {
      type: "string",
      description:
        "A unique identifier for this block. Auto-generated if omitted. Maximum length is 255 characters.",
    },
  }}
/>

Each entry in `elements` is a block-level element: a paragraph, a list, a quote, or a code block.
A block-level element (except a list) in turn holds an array of inline elements: styled text,
links, mentions, emoji, and dates.

<TypeTable
  type={{
    rich_text_section: {
      type: '{ type: "rich_text_section"; elements: RichTextElement[] }',
      description: "A paragraph of inline content, the most common block-level element.",
    },
    rich_text_list: {
      type: '{ type: "rich_text_list"; style: "bullet" | "ordered"; indent?: number; border?: number; elements: RichTextSection[] }',
      description:
        "A list. `indent` (0–8) is its nesting level: a list with a deeper `indent` than the list before it nests under that list's last item; consecutive rich_text_list elements merge into one continuous outline. `border: 1` draws the list inside a quote, which the rich_text_quote elements right after it join, as Slack does.",
    },
    rich_text_quote: {
      type: '{ type: "rich_text_quote"; elements: RichTextElement[] }',
      description: "A blockquote with a colored left bar.",
    },
    rich_text_preformatted: {
      type: '{ type: "rich_text_preformatted"; border?: number; elements: (RichTextText | RichTextLink)[] }',
      description:
        "A monospace code block. A `language` renders it as a syntax-highlighted fenced code block with a copy button; without one it's a plain `<pre>`, whose links keep its text colour. `border: 1` draws it inside a quote, as Slack does.",
    },
  }}
/>

Inline (`RichTextElement`) types: `text` (with `style.bold` / `italic` / `strike` / `code` /
`underline`), `link`, `user`, `usergroup`, `channel`, `broadcast`, `emoji`, `date`, `color`,
`tag`, `salesforce_data_field`, `workflow_mention`, `message_mention`, `file`, `canvas`,
`list_record`, `work_object_mention` and `attachment_mention`.

## Examples

### Section with styled text

Bold, italic, strikethrough, and inline code each come from a `text` element's `style`:

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "text", text: "Hello there, " },
              { type: "text", text: "I am bold", style: { bold: true } },
              { type: "text", text: ", " },
              { type: "text", text: "italic", style: { italic: true } },
              { type: "text", text: ", " },
              { type: "text", text: "struck through", style: { strike: true } },
              { type: "text", text: ", and " },
              { type: "text", text: "code", style: { code: true } },
              { type: "text", text: "." },
            ],
          },
        ],
      },
    ],
  }}
/>

### Indented (nested) list

Consecutive `rich_text_list` elements merge into one outline: a deeper `indent` nests inside the
previous item, and matching a shallower list's `indent`/`style` continues it, numbering on from
where it left off. `offset` (a Builder/undocumented extension to the public schema) sets the
starting number of an `ordered` list that starts a new outline; a list that continues an earlier
one keeps counting and ignores it, as Slack does.

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_list",
            style: "ordered",
            indent: 0,
            border: 1,
            elements: [
              { type: "rich_text_section", elements: [{ type: "text", text: "First" }] },
              { type: "rich_text_section", elements: [{ type: "text", text: "Second" }] },
            ],
          },
          {
            type: "rich_text_list",
            style: "bullet",
            indent: 1,
            elements: [
              { type: "rich_text_section", elements: [{ type: "text", text: "Nested bullet" }] },
            ],
          },
          {
            type: "rich_text_list",
            style: "ordered",
            indent: 0,
            offset: 2,
            elements: [
              { type: "rich_text_section", elements: [{ type: "text", text: "Third (offset)" }] },
            ],
          },
        ],
      },
    ],
  }}
/>

### Preformatted / code block

Without a `language`, preformatted text renders as a plain monospace block:

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_preformatted",
            elements: [{ type: "text", text: "npm install @nkootstra/block-kit" }],
          },
        ],
      },
    ],
  }}
/>

A `language` (a Builder/undocumented extension to the public schema) renders it as a
syntax-highlighted fenced code block instead:

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_preformatted",
            language: "tsx",
            elements: [
              {
                type: "text",
                text: "function Hello({ name }: { name: string }) {\n  return <p>Hello, {name}!</p>;\n}",
              },
            ],
          },
        ],
      },
    ],
  }}
/>

### Links

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "text", text: "Check out " },
              { type: "link", url: "https://slack.com", text: "Slack" },
              { type: "text", text: " or a " },
              {
                type: "link",
                url: "https://example.com",
                text: "styled link",
                style: { italic: true },
              },
              { type: "text", text: "." },
            ],
          },
        ],
      },
    ],
  }}
/>

Resting the pointer on a link shows Slack's link hover card: a "Link" heading with Open in new tab
and Copy link buttons, over the URL as the payload wrote it. Like Slack's, it opens only on hover,
not on keyboard focus, and Escape closes it. A URL the renderer won't follow (such as `javascript:`)
gets no card.

### User, channel, and usergroup mentions

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "text", text: "Hey " },
              { type: "user", user_id: "U0ADA" },
              { type: "text", text: " and " },
              { type: "user", user_id: "U0GRACE" },
              { type: "text", text: ", see " },
              { type: "channel", channel_id: "C0DESIGN" },
              { type: "text", text: " and loop in " },
              { type: "usergroup", usergroup_id: "S0ENG" },
              { type: "text", text: ". " },
              { type: "broadcast", range: "here" },
            ],
          },
        ],
      },
    ],
  }}
/>

:::note
A `user`, `usergroup`, or `channel` mention needs to be resolved to a name to render. The preview
resolves `U0ADA`/`U0GRACE`/`U0ALAN`, `S0ENG`, and `C0GENERAL`/`C0RELEASES`/`C0DESIGN` for you (see
[Mentions and resolvers](/guides/mentions-and-resolvers) for how resolvers work in your own app). An unresolved
`channel` renders as a locked "Private channel" placeholder, with Slack's hover card saying why its
name isn't shown. An unresolved `user` renders a grey loading bar with a "Private user info"
tooltip; when `resolvers.user` is given and doesn't know the user, the user doesn't exist, and the
mention shows Slack's empty outline instead. An unresolved `usergroup` shows the same empty
outline, with an "Unavailable user group info" tooltip.
:::

### Emoji

Text made up only of emoji (and whitespace) renders at a larger "jumbo" size, same as Slack:

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "emoji", name: "rocket" },
              { type: "text", text: " " },
              { type: "emoji", name: "tada" },
              { type: "text", text: " " },
              { type: "emoji", name: "checkered_flag" },
            ],
          },
        ],
      },
    ],
  }}
/>

Mixed into text, emoji render inline at normal text size:

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "text", text: "Nice work " },
              { type: "emoji", name: "wave", skin_tone: 3 },
            ],
          },
        ],
      },
    ],
  }}
/>

### Dates

A `date` element formats a UNIX `timestamp` using curly-brace tokens like `{date_short_pretty}` and
`{time}`; `fallback` is shown if formatting fails, and an optional `url` makes the whole date a link.

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "text", text: "Due " },
              {
                type: "date",
                timestamp: 1767261600,
                format: "{date_short_pretty} at {time}",
                fallback: "Jan 1",
              },
            ],
          },
        ],
      },
    ],
  }}
/>

### Tag

A `tag` element (a Builder/undocumented extension) draws its `text` as a coloured label, 24px tall,
so its line is 2px taller than plain text. Slack's blue is the only colour captured so far; every
`color` draws as blue, from `--sbk-tag-bg` and `--sbk-tag-text`.

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "text", text: "See " },
              { type: "tag", text: "In progress", color: "blue" },
            ],
          },
        ],
      },
    ],
  }}
/>

### Salesforce data field

A `salesforce_data_field` element (a Builder/undocumented extension) points at a field of a
Salesforce record. The renderer can't read the record, so it draws the field as Slack draws one it
can't reach: a greyed pill, 24px tall, with Salesforce's cloud and "Record was deleted". The
record's ID is on the pill as `data-id`.

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "text", text: "See " },
              {
                type: "salesforce_data_field",
                salesforce_record_id: "001000000000001",
                salesforce_field_label: "Amount",
                salesforce_include_field_label: true,
              },
            ],
          },
        ],
      },
    ],
  }}
/>

### Workflows, messages, files, canvases, lists and work objects

These elements point at something only Slack can look up. The renderer shows each the way Slack
shows it to someone who can't open it, whatever `text` the payload gives:

| Element               | Shows                                                                     |
| --------------------- | ------------------------------------------------------------------------- |
| `workflow_mention`    | A greyed pill with a trash can and "Deleted workflow"                     |
| `message_mention`     | A greyed pill with a speech bubble and "Private message"                  |
| `file`                | A greyed pill with a closed eye and "Hidden file"                         |
| `canvas`              | A blue pill with a lock and "Private canvas"                              |
| `list_record`         | A blue pill with a lock and "Private list"                                |
| `work_object_mention` | A blue pill with the app's icon and the element's `text`, linked to `url` |
| `attachment_mention`  | The element's `text` as a link to `url`, without an underline             |

A work object's icon is a square in the colour of a message's placeholder avatar: Slack shows the
app's icon, which the renderer can't load.

<Preview
  payload={{
    blocks: [
      {
        type: "rich_text",
        elements: [
          {
            type: "rich_text_section",
            elements: [
              { type: "text", text: "See " },
              { type: "canvas", file_id: "F0123456789", text: "A canvas" },
              { type: "text", text: " and " },
              {
                type: "work_object_mention",
                entity_id: "E0123456789",
                app_id: "A0123456789",
                text: "A work object",
                url: "https://example.com/work-object",
              },
            ],
          },
        ],
      },
    ],
  }}
/>
