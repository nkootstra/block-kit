`contact_card` shows the name for a Slack user id, resolved the same way a mention is. It doesn't
appear in the public `@slack/types` package, so treat this page's field list as the reference.

<Preview
  payload={{
    blocks: [{ type: "contact_card", contact_user_id: "U0ADA" }],
  }}
/>

## Examples

### Resolved user

The preview above resolves `U0ADA` to Ada Lovelace using the preview's sample directory. In your own
app, wire up a [resolver](/guides/mentions-and-resolvers) backed by the Slack Web API so real user ids
resolve to real names. The lookups run on your server, through a resolver relay or before the page
renders, so the bot token never reaches the browser: see
[Keep the bot token on the server](/guides/mentions-and-resolvers#keep-the-bot-token-on-the-server).

### Workspace name

Under the name, Slack shows the contact's workspace. Pass it as `identity.teamName` on
[`BlockKitProvider`](/reference/block-kit-provider); without it the card says "Contact".

```tsx
<BlockKitProvider identity={{ teamName: "Acme" }} resolvers={resolvers}>
```

### Unknown user

<Preview
  payload={{
    blocks: [{ type: "contact_card", contact_user_id: "U0123456789" }],
  }}
/>

When `resolvers.user` is given and doesn't know the id, the user doesn't exist as far as the card
can tell, so it shows "This content could not be displayed.", as Slack does for a user that doesn't
exist. With no `resolvers.user` at all, the lookup counts as pending, and the card shows the
placeholder skeleton Slack shows while it looks the user up.

### Inside a container

<Preview
  payload={{
    blocks: [
      {
        type: "container",
        title: { type: "plain_text", text: "Team" },
        child_blocks: [{ type: "contact_card", contact_user_id: "U0ADA" }],
      },
    ],
  }}
/>

:::warning
Slack can't display a `contact_card` nested inside a [container](/blocks/container), including one
nested inside a [callout](/blocks/callout) that's itself inside a container, and shows "This content
could not be displayed" instead. This library matches that behavior so a payload previews the way it
would in Slack.
:::
