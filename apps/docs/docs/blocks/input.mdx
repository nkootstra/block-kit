`input` pairs a label with one form element: a text field, a select, a date or time picker,
checkboxes, or radio buttons. It's the field type modals and App Home tabs use to collect values a
user submits; message and card surfaces never render it.

## Fields

    hint: {
      type: "PlainTextElement",
      description: "Muted helper text below the element. Maximum length is 2000 characters.",
    },
    optional: {
      type: "boolean",
      description:

      default: "false",
    },
    dispatch_action: {
      type: "boolean",
      description:
        "Sends a `block_actions` payload as the user interacts with the element. Without it, the value only arrives on submit.",
      default: "false",
    },
    block_id: {
      type: "string",
      description:
        "A unique identifier for this block. Auto-generated if omitted. Maximum length is 255 characters.",
    },
  }}
/>

:::note
`element` accepts one of `checkboxes`, `datepicker`, `datetimepicker`, `email_text_input`,
`file_input`, `plain_text_input` (including `multiline: true`), `radio_buttons`, `rich_text_input`,
`static_select` / `multi_static_select`, `external_select` / `multi_external_select`,
`users_select` / `multi_users_select`, `conversations_select` / `multi_conversations_select`,
`channels_select` / `multi_channels_select`, `timepicker`, and `number_input` / `url_text_input`.
Every option's own fields (placeholders, options, initial values) work exactly as they do on
[actions](/blocks/actions) or a section accessory.
:::

## Interactivity

By default an `input` block's element sends no actions: its value only reaches `state`, and your
app reads it from the `view_submission` payload. Set `dispatch_action: true` to also get a
`block_actions` payload as the user interacts, like an element in an `actions` block.

Checkboxes, radio buttons, selects and pickers then dispatch on every change. Text inputs
(`plain_text_input`, `email_text_input`, `url_text_input`, `number_input`) and `rich_text_input`
dispatch on the trigger in their `dispatch_action_config`, which Slack gives all five:

- `on_enter_pressed` (the default): Enter sends the action. A multiline `plain_text_input` never
  dispatches on Enter, which inserts a newline instead; in a `rich_text_input`, Shift+Enter adds a
  line.
- `on_character_entered`: one action with the full value once typing pauses for 300ms. Slack
  coalesces keystrokes the same way (Block Kit Builder sends a single action for a quickly typed
  word) without documenting its interval. An Enter dispatch is sent at once.

Block Kit Builder sends nothing on Enter from a `url_text_input` or `rich_text_input`; the package
follows Slack's docs, which give both elements `dispatch_action_config`.

## State in a modal or Home tab

A view's `state.values` holds every input block's element, as in Slack's `view_submission`: one the
user hasn't touched is reported with its empty value, `null` for a single value (`value`,
`selected_option`, `selected_date`, `selected_user`, …) and `[]` for a multi-value element
(`selected_options`, `selected_users`, …). A `rich_text_input` is reported as just its `type`, and
an initial value is reported as set. In a message, only elements with a value are reported.

<Preview
  actions
  payload={{
    blocks: [
      {
        dispatch_action: true,
        type: "input",
        label: { type: "plain_text", text: "Label" },
        element: { type: "plain_text_input", action_id: "plain_text_input-action" },
      },
    ],
  }}
/>

`onAction` receives, on pressing Enter:

```json
{
  "type": "plain_text_input",
  "action_id": "plain_text_input-action",
  "block_id": "<the input block's block_id>",
  "value": "…"
}
```

A single-line `on_enter_pressed`-dispatching input shows a "Press 'enter' to submit" hint below
it, matching Slack's Builder preview. With the block's own `hint`, both share one line, the hint
ending in a period:

<Preview
  payload={{
    blocks: [
      {
        dispatch_action: true,
        type: "input",
        label: { type: "plain_text", text: "Label" },
        element: {
          type: "plain_text_input",
          action_id: "plain_text_input-action",
        },
      },
    ],
  }}
/>

Any other element dispatches on change. Tick a box to see the action:
