`plan` groups a sequence of tasks under one shared goal, each with its own status. It's a [Slack
block documented for agent surfaces](https://docs.slack.dev/reference/block-kit/blocks/plan-block/),
newer than the version of `@slack/types` this library depends on, so its TypeScript type is the field
reference here. It's read-only: expanding a plan doesn't emit an action.

Click the pill to expand the plan and see each task's details, output, and sources.

Statuses show as icons, so screen readers hear them as text after each title instead: "complete",
"in progress", "pending" or "failed", on the pill and on every task. A task's title is a button only
when the task has something to show; a task with no `details`, `output` or `sources` is plain text,
not a disabled button. As in Slack, each expanded task is a list item the keyboard can focus, so Tab
steps through a long plan task by task, with the focus ring around the whole task.

### PlanTask

A plan's tasks share the same shape as a standalone [task card](/blocks/task-card):

<TypeTable
  type={{
    task_id: {
      type: "string",
      description: "Identifies the task.",
      required: true,
    },
    title: {
      type: "string",
      description: "The task's one-line summary.",
      required: true,
    },
    status: {
      type: '"pending" | "in_progress" | "complete" | "error"',
      description:
        "The task's state. On the timeline, `in_progress` shows a blue spinner, `error` a red warning, and `complete` and `pending` a grey dot, lighter while pending.",
      required: true,
    },
    details: {
      type: "RichTextBlock",
      description: "What the task is doing, shown when the plan is expanded.",
    },
    output: {
      type: "RichTextBlock",
      description: "The task's result, shown below `details`.",
    },
    sources: {
      type: '{ type: "url"; url: string; text?: string }[]',
      description: "Links shown under the task. `text` defaults to the raw URL.",
    },
  }}
/>

The plan's own collapsed pill shows one status for the whole plan: in progress (a spinner) while any
task is still pending or in progress, then failed (a warning) if any task failed, else complete (a
check).
