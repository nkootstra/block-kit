In this guide you render a message with two buttons, handle the click, and replace the buttons with the outcome, the same flow a Slack app runs with `response_url`.

This guide assumes you've finished [Installation](/installation): the package is installed, and
its stylesheet and fonts are imported once at the root of your app (in Next.js, `app/layout.tsx`;
in Vite, `src/main.tsx`). Without them the message renders unstyled:

```tsx app/layout.tsx or src/main.tsx
import "@nkootstra/block-kit/styles.css";
import "@fontsource/lato/400.css";
import "@fontsource/lato/400-italic.css";
import "@fontsource/lato/700.css";
import "@fontsource/lato/900.css";
import "@fontsource/roboto-mono/400.css";
```

<Steps>
<Step title="Render the message">

Pass the `blocks` your app sends to `chat.postMessage` straight to `<Message>`:

```tsx Approval.tsx
"use client";

import { Message } from "@nkootstra/block-kit";

const blocks = [
  {
    type: "section",
    text: { type: "mrkdwn", text: "<@U0ADA> wants to deploy *api@4.2.0* to production." },
  },
  {
    type: "actions",
    block_id: "deploy",
    elements: [
      {
        type: "button",
        style: "primary",
        action_id: "approve",
        value: "api@4.2.0",
        text: { type: "plain_text", text: "Approve" },
      },
      {
        type: "button",
        action_id: "reject",
        value: "api@4.2.0",
        text: { type: "plain_text", text: "Reject" },
      },
    ],
  },
];

export default function Approval() {
  return (
    <Message
      app={{ name: "Deploy Bot" }}
      // The message's own Slack timestamp, and the zone to show it in, so a server render and
      // the browser show the same time. See Server rendering.
      ts="1790856000.000100"
      timeZone="UTC"
      blocks={blocks}
    />
  );
}
```

`"use client"` marks the file as a Client Component for the Next.js App Router, because the next
step passes a function to the provider and functions can't cross from a Server Component. Vite and
other client-only setups ignore it. `ts` and `timeZone` keep the time next to the app name the same
in the server's HTML and in the browser; without them a server-rendered message logs a hydration
mismatch ([Server rendering](/guides/server-rendering#hydration-stable-timestamps)).

<Step title="Handle the click">

Wrap the message in a `<BlockKitProvider>` and pass `onAction`. It receives each action in the shape of one entry of a `block_actions` payload's `actions` array:

```tsx Approval.tsx
"use client";

import { BlockKitProvider, Message, type BlockAction } from "@nkootstra/block-kit";

// `blocks` as in step 1.

function handleAction(action: BlockAction) {
  console.log(action.action_id, action.value);
  // → "approve" "api@4.2.0"
}

export default function Approval() {
  return (
    <BlockKitProvider onAction={handleAction}>
      <Message app={{ name: "Deploy Bot" }} ts="1790856000.000100" timeZone="UTC" blocks={blocks} />
    </BlockKitProvider>
  );
}
```

<Step title="Update the message">

The second argument to `onAction` lets you answer the way an app would. `message.update` replaces the message the action came from, like posting to `response_url` with `replace_original`:

```tsx Approval.tsx
"use client";

import {
  BlockKitProvider,
  Message,
  type ActionContext,
  type BlockAction,
} from "@nkootstra/block-kit";

// `blocks` and `Approval` stay as in step 2; only `handleAction` changes.

function handleAction(action: BlockAction, { message }: ActionContext) {
  const verdict = action.action_id === "approve" ? ":white_check_mark: Approved" : ":x: Rejected";

  // A demo: anyone who clicks approves, and the reviewer is always the same. See the note below.
  message?.update({
    blocks: [
      blocks[0],
      { type: "context", elements: [{ type: "mrkdwn", text: `${verdict} by <@U0GRACE>` }] },
    ],
  });
}
```

After a click, the message becomes:

<Preview

  resolve={false}
  payload={{
    blocks: [
      {
        type: "section",
        text: { type: "mrkdwn", text: "<@U0ADA> wants to deploy *api@4.2.0* to production." },

      {
        type: "context",

      },
    ],
  }}
/>

The context also has `views`, to open a modal, and `state`, with the current value of every input in the message.

:::warning
This handler decides the outcome in the browser, which is fine for a preview and nothing more:
anyone who can open the page can call it. In a real app the click goes to your server, which works
out who clicked from its own session (or from `user.id` in a request whose Slack signature it
checked), checks that they may approve this deploy, and only then updates the message.
[In production](/guides/interactivity#in-production) shows the wiring, and
[Untrusted input](/guides/untrusted-input) what the server checks.
:::

</Step>
</Steps>

## Already have a Slack app?

If your app already handles interactions, with Bolt or your own request URL, you don't need to rewrite its logic in React while you develop. Relay the clicks to it instead, and apply whatever it answers: see [Connecting your app](/guides/connecting-your-app). The relay is development and preview tooling; in production, clicks go to a route of your own ([In production](/guides/interactivity#in-production)).
